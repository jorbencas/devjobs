------------------------------------------------------------------------------
  CÓMO LEER ESTO (regla común para todos los proyectos)
------------------------------------------------------------------------------
Todos los alias se instalan una vez con:
      bash servicios/instalar_aliases.sh && source ~/.bashrc
Valen desde CUALQUIER carpeta (usan `-f`).

Si un proyecto corre en 2 MODOS, cada modo tiene sus propios alias:
   *_logs / *_stop / *_restart   → instancia DAEMON (la de PRODUCCIÓN, 24/7)
   *_manual_*                    → instancia para PROBAR a mano (normalmente --rm)
   *_down                        → parar TODO el proyecto (ambas instancias)

Las herramientas MANUALES son CLIs interactivas (menú con teclado): se lanzan
con `docker compose run --rm` (servicios con `stdin_open` + `tty`), así que
EJECÚTALAS DESDE UNA TERMINAL REAL (no desde una sesión sin TTY ni scripts), y
recarga los alias con `source ~/.bashrc` tras reinstalarlos.

==============================================================================
  1. DOCKER GENERAL
==============================================================================

--- Imágenes ---
docker images                          # Listar imágenes
docker rmi <image>                     # Eliminar imagen
docker image prune                     # Limpiar imágenes sin usar
docker image prune -a                  # Limpiar TODAS las imágenes sin usar

--- Contenedores ---
docker ps                              # Contenedores activos
docker ps -a                           # Todos los contenedores
docker stop <container>                # Parar contenedor
docker rm <container>                  # Eliminar contenedor
docker rm -f <container>               # Eliminar forzadamente
docker container prune                 # Limpiar contenedores detenidos
docker logs <container>                # Ver logs
docker logs -f <container>             # Ver logs en tiempo real
docker exec -it <container> bash       # Entrar al contenedor
docker inspect <container>             # Info detallada

--- Limpieza general ---
docker system prune                    # Limpiar todo (contenedores, redes, imágenes)
docker system prune -a                 # Limpieza agresiva
docker volume prune                    # Limpiar volúmenes no usados

--- Build ---
docker build -t <name> .               # Construir imagen desde Dockerfile
docker build --no-cache -t <name> .    # Construir sin caché

--- Ejecución ---
docker run --rm -it <image> bash       # Ejecutar y entrar interactivamente
docker run -d <image>                  # Ejecutar en background (detached)
docker run -p 8080:80 <image>          # Exponer puertos
docker run -v /host:/container <image> # Montar volúmenes

--- Redes ---
docker network ls                      # Listar redes
docker network inspect <network>       # Info de red

==============================================================================
  2. DOCKER COMPOSE
==============================================================================

--- Comandos básicos ---
docker compose up                      # Arrancar servicios (foreground)
docker compose up -d                   # Arrancar en background
docker compose up --build              # Re-construir y arrancar
docker compose down                    # Parar y eliminar contenedores
docker compose down -v                 # Parar y eliminar contenedores + volúmenes
docker compose ps                      # Estado de servicios
docker compose logs                    # Ver logs
docker compose logs -f                 # Logs en tiempo real
docker compose logs -f <service>       # Logs de un servicio específico

--- Build ---
docker compose build                   # Construir imágenes
docker compose build --no-cache        # Re-construir sin caché

--- Ejecución ---
docker compose run <service>           # Ejecutar servicio una vez
docker compose run --rm <service>      # Ejecutar y eliminar al terminar
docker compose run --rm --service-ports <service>  # Con puertos expuestos
docker compose run -e VAR=value <service>  # Con variable de entorno

--- Shell / Restart / Escalado ---
docker compose exec <service> bash     # Entrar al servicio corriendo
docker compose restart                 # Reiniciar servicios
docker compose restart <service>       # Reiniciar un servicio
docker compose up --scale <service>=3  # Escalar servicio

  TODO el proyecto

------------------------------------------------------------------------------
3F. FFMPEG-YT-DLP  (2 modos)           — forma parte del pipeline (paso 2)
------------------------------------------------------------------------------
Qué hace: conversor/optimizador de vídeo (midu.sh) + un "monitor" que comprime
automáticamente a 720p las grabaciones entrantes. En el pipeline es quien
convierte `*_completed.mp4` → `*_compressed.mp4`.

  DAEMON — monitor (parte del pipeline)      contenedor: ffmpeg_monitor
    ff_logs       Ver la conversión en curso (cómo va el ffmpeg_monitor)
    ff_stop       Pararlo
    ff_restart    Reiniciarlo

  MANUAL — midu interactivo
    ff_midu            Lanzar midu.sh INTERACTIVO (docker compose run --rm):
                       asigna TTY + stdin para poder usar el menú.
                       Usa SOLO el servicio downloader (no toca al monitor).
                       contenedor: yt_ffmpeg_downloader
    ff_manual_logs     Ver logs del midu
    ff_manual_stop     Pararlo

  Preview Watcher (host/WSL, NO es Docker)
    watcher / watcher_daemon / watcher_stop / watcher_status

Notas: `ff_logs` es lo que pones para seguir la compresión del monitor.

==============================================================================
  4. PIPELINE: DIRECTO SENDO SAMA → TELEGRAM
==============================================================================

Encadena los pasos de 3 proyectos (TwitchRecorder → ffmpeg-yt-dlp →
downloader_telegram): graba el directo, lo comprime a 720p y lo sube a los
grupos de Telegram. Ejecuta/paras los 3 DAEMONS a la vez:

  pipe_up            ➜ EJECUTAR TODO EL PIPELINE DE UNA VEZ
  pipe_down          ➜ Parar los 3 daemons
  plogs                 Logs de los 3 a la vez con color (azul/amarillo/rojo)
  pipe_ps               Estado de los 3 contenedores
  pipe_recreate         Recrear los 3 (aplica cambios de config)
  pipe_rebuild          Rebuild + recrear los 3 (si cambiaste CÓDIGO)
  pipe_setup            Login Telegram del uploader (teléfono+código, UNA vez)
  pipe_chats [args]     Listar chats: [--creados] [--folder <texto>]
  pipe_chats_sendo      Solo la carpeta "sendo"
  pipe_test [kw] [ruta] Probar subida de un video
  pipe_sys_start/stop/status   Arrancar/parar/ver estado (systemd)

--- Setup inicial (SOLO la primera vez) ---
pipe_setup             # login Telegram del uploader (teléfono + código)
pipe_chats --creados   # ver tus canales/grupos con IDs → rellena grupos.json

--- Carpetas ---
test_videos/test/        Grabaciones terminadas (*_KW_<kw>_completed.mp4)
Videos/comprimidos/      Videos listos para subir (*_KW_<kw>_compressed.mp4)
test_videos_backup/      Grabaciones antiguas archivadas

# Config (grupos.json, credenciales, sesiones, ruteo por keyword): ver README_UPLOADER.md
# NO uses `docker compose down` a secas en downloader_telegram / TwitchRecorder /
# ffmpeg-yt-dlp (pararían también al daemon del pipeline). Para parar los 3 usa pipe_down.

==============================================================================
  5. AUTO-ARRANQUE AL ENCENDER EL PC (SYSTEMD)
==============================================================================

Los 3 daemons del pipeline se levantan solos al boot. Instalar una vez (requiere sudo):

sudo systemctl enable /home/jorge/dev/devjobs/servicios/twitch-stream-pipeline.service

Operación manual (alias de ~/.bashrc):
pipe_sys_start        # Arrancar el pipeline
pipe_sys_stop         # Parar todo
pipe_sys_status       # Ver estado

# Nota: tras pipe_recreate/pipe_up los contenedores ya están arriba; systemctl
# solo gestiona el arranque al boot. Detalle del servicio: ver README.md.

==============================================================================
  6. MONTAR EN OTRA MÁQUINA (Windows + WSL2)
==============================================================================

Un solo script hace el montaje completo: clona el repo, ajusta las rutas a la
máquina nueva, crea carpetas, revisa secretos, build, systemd y aliases:

   bash <(curl -fsSL https://raw.githubusercontent.com/jorbencas/devjobs/main/servicios/bootstrap_instalar.sh)

El script te pedirá confirmación antes de tocar rutas y te avisará qué secretos
faltan (config.bin/secret.key, uploader.session, grupos.json). Re-lanzable: es
idempotente y seguro.

--- Paso 0: preparar WSL desde cero (SOLO la primera vez) ---

  1. Instala WSL + una distro (Ubuntu). En PowerShell como ADMINISTRADOR:
       wsl --install -d Ubuntu
     (si WSL ya estaba, para renovar:  wsl --update && wsl --set-default-version 2)
  2. Reinicia el PC si te lo pide. Al abrir Ubuntu crea tu usuario/contraseña.
  3. Activa SYSTEMD en la distro (necesario para el auto-arranque). Dentro de
     Ubuntu crea/edita /etc/wsl.conf (con sudo):
       [boot]
       systemd=true
     y reinicia WSL desde PowerShell:
       wsl --shutdown
  4. Instala Docker Desktop (Windows) y actívalo: Settings → Resources → WSL
     integration → activa tu distro (Ubuntu). Espera a que diga "Engine running".
  5. Vuelve a abrir Ubuntu y lanza el bootstrap de arriba. El propio script
     comprueba Docker y, si detecta WSL sin systemd, te deja el /etc/wsl.conf
     preparado para reiniciar.
