  1. DOCKER GENERAL
==============================================================================

--- Imágenes ---
docker images                          # Listar imágenes
docker rmi <image>                     # Eliminar imagen
docker image prune                     # Limpiar imágenes sin usar
docker image prune -a                  # Limpiar TODAS las imágenes sin usar

--- Contenedores ---
docker ps                              # Contenedores activos
docker ps -a                           # Todos los contenedores
docker stop <container>                # Parar contenedor
docker rm <container>                  # Eliminar contenedor
docker rm -f <container>               # Eliminar forzadamente
docker container prune                 # Limpiar contenedores detenidos
docker logs <container>                # Ver logs
docker logs -f <container>             # Ver logs en tiempo real
docker exec -it <container> bash       # Entrar al contenedor
docker inspect <container>             # Info detallada

--- Limpieza general ---
docker system prune                    # Limpiar todo (contenedores, redes, imágenes)
docker system prune -a                 # Limpieza agresiva
docker volume prune                    # Limpiar volúmenes no usados

--- Build ---
docker build -t <name> .               # Construir imagen desde Dockerfile
docker build --no-cache -t <name> .    # Construir sin caché

--- Ejecución ---
docker run --rm -it <image> bash       # Ejecutar y entrar interactivamente
docker run -d <image>                  # Ejecutar en background (detached)
docker run -p 8080:80 <image>          # Exponer puertos
docker run -v /host:/container <image> # Montar volúmenes

--- Redes ---
docker network ls                      # Listar redes
docker network inspect <network>       # Info de red

==============================================================================
  2. DOCKER COMPOSE
==============================================================================

--- Comandos básicos ---
docker compose up                      # Arrancar servicios (foreground)
docker compose up -d                   # Arrancar en background
docker compose up --build              # Re-construir y arrancar
docker compose down                    # Parar y eliminar contenedores
docker compose down -v                 # Parar y eliminar contenedores + volúmenes
docker compose ps                      # Estado de servicios
docker compose logs                    # Ver logs
docker compose logs -f                 # Logs en tiempo real
docker compose logs -f <service>       # Logs de un servicio específico

--- Build ---
docker compose build                   # Construir imágenes
docker compose build --no-cache        # Re-construir sin caché

--- Ejecución ---
docker compose run <service>           # Ejecutar servicio una vez
docker compose run --rm <service>      # Ejecutar y eliminar al terminar
docker compose run --rm --service-ports <service>  # Con puertos expuestos
docker compose run -e VAR=value <service>  # Con variable de entorno

--- Shell / Restart / Escalado ---
docker compose exec <service> bash     # Entrar al servicio corriendo
docker compose restart                 # Reiniciar servicios
docker compose restart <service>       # Reiniciar un servicio
docker compose up --scale <service>=3  # Escalar servicio

./menu.sh --clear-profile              # Menú con perfil limpio

  5. PIPELINE: DIRECTO SENDO SAMA → TELEGRAM
==============================================================================

Encadena 3 proyectos: grabar → comprimir → subir automáticamente a Telegram.
Ver README.md (raíz de devjobs) y README_MONITOR.md / README_UPLOADER.md.

--- Flujo ---
TwitchRecorder (grabar) → test/*_KW_<keyword>_completed.mp4   (keyword del título del directo)
  → ffmpeg-yt-dlp monitor (720p) → /home/jorge/dev/devjobs/Videos/comprimidos/*_KW_<keyword>_compressed.mp4
  → downloader_telegram uploader → ruteo por keyword (grupo cuyo nombre coincida, si no default)

--- Preparación inicial (solo una vez, ANTES de dejarlo solo) ---
cd /home/jorge/dev/devjobs/downloader_telegram
docker compose build
touch uploader.session                          # crear archivo vacío si no existe (si no, Docker lo monta como dir → falla la sesión)
docker compose run --rm uploader python /app/subir_videos.py --setup     # pide teléfono+código, crea uploader.session
docker compose run --rm uploader python /app/subir_videos.py --list-chats          # descubre IDs de tus grupos
docker compose run --rm uploader python /app/subir_videos.py --list-chats --folder "sendo" # solo esa carpeta
docker compose run --rm uploader python /app/subir_videos.py --list-chats --creados # solo lo que creaste tú
# Edita grupos.json: "default" + grupos [{nombre, id}]  (ver README_UPLOADER.md)

--- Arrancar TODO el pipeline ---
cd /home/jorge/dev/devjobs/TwitchRecorder && docker compose up -d twitchrecorder
cd /home/jorge/dev/devjobs/ffmpeg-yt-dlp && docker compose up -d monitor
cd /home/jorge/dev/devjobs/downloader_telegram && docker compose up -d uploader

--- Parar TODO ---
docker compose -f /home/jorge/dev/devjobs/TwitchRecorder/docker-compose.yml down
docker compose -f /home/jorge/dev/devjobs/ffmpeg-yt-dlp/docker-compose.yml down
docker compose -f /home/jorge/dev/devjobs/downloader_telegram/docker-compose.yml down

--- Estado / logs (sirven desde CUALQUIER carpeta, usan -f con ruta absoluta) ---
docker ps                                                            # Qué contenedores del pipeline están arriba
docker compose -f /home/jorge/dev/devjobs/TwitchRecorder/docker-compose.yml logs -f
docker compose -f /home/jorge/dev/devjobs/ffmpeg-yt-dlp/docker-compose.yml logs -f monitor
docker compose -f /home/jorge/dev/devjobs/downloader_telegram/docker-compose.yml logs -f uploader

--- Carpetas ---
/home/jorge/dev/devjobs/test_videos/test/ # Grabaciones terminadas (*_KW_<keyword>_completed.mp4)
/home/jorge/dev/devjobs/Videos/comprimidos/ # Videos listos para subir (*_KW_<keyword>_compressed.mp4)
/home/jorge/dev/devjobs/test_videos_backup/ # Grabaciones antiguas archivadas

==============================================================================
  6. AUTO-ARRANQUE AL ENCENDER EL PC (SYSTEMD)
==============================================================================

El pipeline (twitchrecorder + monitor + uploader) se levanta solo al arrancar el
sistema mediante un servicio systemd. Docker ya está habilitado en el boot.

--- Instalar (una vez, requiere sudo) ---
sudo systemctl enable /home/jorge/dev/devjobs/servicios/twitch-stream-pipeline.service

--- Operación manual ---
sudo systemctl start   twitch-stream-pipeline.service   # Arrancar el pipeline
sudo systemctl stop    twitch-stream-pipeline.service   # Parar todo
sudo systemctl restart twitch-stream-pipeline.service   # Reiniciar
sudo systemctl status  twitch-stream-pipeline.service   # Ver estado

# Detalle del servicio: ver README.md (raíz de devjobs)
