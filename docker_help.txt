------------------------------------------------------------------------------
  CÓMO LEER ESTO (regla común para todos los proyectos)
------------------------------------------------------------------------------
Todos los alias se instalan una vez con:
      bash servicios/instalar_aliases.sh && source ~/.bashrc
Valen desde CUALQUIER carpeta (usan `-f`).

Si un proyecto corre en 2 MODOS, cada modo tiene sus propios alias:
   *_logs / *_stop / *_restart   → instancia DAEMON (la de PRODUCCIÓN, 24/7)
   *_manual_*                    → instancia para PROBAR a mano (normalmente --rm)
   *_down                        → parar TODO el proyecto (ambas instancias)

Si un proyecto tiene BOT API, tiene sus propios alias:
   tg_bot / tg_bot_logs / tg_bot_stop / tg_bot_restart / tg_bot_rebuild
   tg_bot_sys_start / tg_bot_sys_stop / tg_bot_sys_status

Las herramientas MANUALES son CLIs interactivas (menú con teclado): se lanzan
con `docker compose run --rm` (servicios con `stdin_open` + `tty`), así que
EJECÚTALAS DESDE UNA TERMINAL REAL (no desde una sesión sin TTY ni scripts), y
recarga los alias con `source ~/.bashrc` tras reinstalarlos.

==============================================================================
  1. DOCKER GENERAL
==============================================================================

--- Imágenes ---
docker images                          # Listar imágenes
docker rmi <image>                     # Eliminar imagen
docker image prune                     # Limpiar imágenes sin usar
docker image prune -a                  # Limpiar TODAS las imágenes sin usar

--- Contenedores ---
docker ps                              # Contenedores activos
docker ps -a                           # Todos los contenedores
docker stop <container>                # Parar contenedor
docker rm <container>                  # Eliminar contenedor
docker rm -f <container>               # Eliminar forzadamente
docker container prune                 # Limpiar contenedores detenidos
docker logs <container>                # Ver logs
docker logs -f <container>             # Ver logs en tiempo real
docker exec -it <container> bash       # Entrar al contenedor
docker inspect <container>             # Info detallada

--- Limpieza general ---
docker system prune                    # Limpiar todo (contenedores, redes, imágenes)
docker system prune -a                 # Limpieza agresiva
docker volume prune                    # Limpiar volúmenes no usados

--- Build ---
docker build -t <name> .               # Construir imagen desde Dockerfile
docker build --no-cache -t <name> .    # Construir sin caché

--- Ejecución ---
docker run --rm -it <image> bash       # Ejecutar y entrar interactivamente
docker run -d <image>                  # Ejecutar en background (detached)
docker run -p 8080:80 <image>          # Exponer puertos
docker run -v /host:/container <image> # Montar volúmenes

--- Redes ---
docker network ls                      # Listar redes
docker network inspect <network>       # Info de red

==============================================================================
  2. DOCKER COMPOSE
==============================================================================

--- Comandos básicos ---
docker compose up                      # Arrancar servicios (foreground)
docker compose up -d                   # Arrancar en background
docker compose up --build              # Re-construir y arrancar
docker compose down                    # Parar y eliminar contenedores
docker compose down -v                 # Parar y eliminar contenedores + volúmenes
docker compose ps                      # Estado de servicios
docker compose logs                    # Ver logs
docker compose logs -f                 # Logs en tiempo real
docker compose logs -f <service>       # Logs de un servicio específico

--- Build ---
docker compose build                   # Construir imágenes
docker compose build --no-cache        # Re-construir sin caché

--- Ejecución ---
docker compose run <service>           # Ejecutar servicio una vez
docker compose run --rm <service>      # Ejecutar y eliminar al terminar
docker compose run --rm --service-ports <service>  # Con puertos expuestos
docker compose run -e VAR=value <service>  # Con variable de entorno

--- Shell / Restart / Escalado ---
docker compose exec <service> bash     # Entrar al servicio corriendo
docker compose restart                 # Reiniciar servicios
docker compose restart <service>       # Reiniciar un servicio
docker compose up --scale <service>=3  # Escalar servicio

    docker compose -f yt-to-telegram/docker-compose.yml run --rm yt-download

  Solo convertir (test):
    docker compose -f yt-to-telegram/docker-compose.yml run --rm yt-convert

  Solo subir (test):
    docker compose -f yt-to-telegram/docker-compose.yml run --rm yt-upload

    data/yt-pipeline/downloads/    Vídeos descargados de YouTube
    data/yt-pipeline/converted/    Vídeos convertidos para Telegram
    data/yt-pipeline/uploaded/     Histórico de vídeos subidos

==============================================================================
  4. PIPELINE: DIRECTO SENDO SAMA → TELEGRAM
==============================================================================

Encadena los pasos de 3 proyectos (TwitchRecorder → ffmpeg-yt-dlp →
downloader_telegram): graba el directo, lo comprime a 720p y lo sube a los
grupos de Telegram. Ejecuta/paras los 3 DAEMONS a la vez:

  pipe_up            ➜ EJECUTAR TODO EL PIPELINE DE UNA VEZ
  pipe_down          ➜ Parar los 3 daemons
  plogs                 Logs de los 3 a la vez con color (azul/amarillo/rojo)
  pipe_ps               Estado de los 3 contenedores
  pipe_recreate         Recrear los 3 (aplica cambios de config)
  pipe_rebuild          Rebuild + recrear los 3 (si cambiaste CÓDIGO)
  pipe_setup            Login Telegram del uploader (teléfono+código, UNA vez)
  pipe_chats [args]     Listar chats: [--creados] [--folder <texto>]
  pipe_chats_sendo      Solo la carpeta "sendo"
  pipe_topics <grupo>   Listar los temas (series) de un grupo con foro → rellena "temas"
  pipe_once             Una sola pasada del uploader (sube lo pendiente y sale)
  pipe_test [kw] [ruta] Probar subida de un video
  pipe_sys_start/stop/status   Arrancar/parar/ver estado (systemd)

--- Setup inicial (SOLO la primera vez) ---
pipe_setup             # login Telegram del uploader (teléfono + código)
pipe_chats --creados   # ver tus canales/grupos con IDs → rellena grupos.json
pipe_topics <grupo>    # si el grupo es un foro: lista los temas (series) → rellena "temas"

--- Carpetas ---
data/grabaciones/test/   Grabaciones terminadas (*_KW_<kw>_completed.mp4)
data/comprimidos/        Videos listos para subir (*_KW_<kw>_compressed.mp4)
data/backups/            Grabaciones antiguas archivadas

--- Conversión (todos los pipelines usan lo mismo) ---
  ffmpeg -c:v libx264 -crf 28 -preset fast -vf scale=-2:720
  -c:a aac -b:a 128k -map 0:v:0 -map 0:a:0 -map_metadata 0
  -movflags +faststart -f mp4
  2 pasadas si >50MB (Telegram) o >1900MB (uploader)

# Config (grupos.json, credenciales, sesiones, ruteo por keyword): ver
# downloader_telegram/README.md (sección "Uploader a Telegram")
# NO uses `docker compose down` a secas en downloader_telegram / TwitchRecorder /
# ffmpeg-yt-dlp (pararían también al daemon del pipeline). Para parar los 3 usa pipe_down.

--- Eliminar videos de Telegram (uso manual) ---
  cd downloader_telegram
  docker compose run --rm uploader python /app/app/subir_videos.py --delete-videos GRUPO_ID
  # O con topics específicos:
  docker compose run --rm uploader python /app/app/subir_videos.py --delete-videos GRUPO_ID --topics 26,27,28
  # dry-run (solo mostrar, no borrar):
  docker compose run --rm uploader python /app/app/subir_videos.py --delete-videos GRUPO_ID --dry-run

==============================================================================
  5. PIPELINE VÍA SYSTEMD (AUTO-ARRANQUE AL BOOT)
==============================================================================

Los 3 daemons del pipeline (grabar → comprimir → subir) se levantan solos al
encender el PC gracias al servicio systemd. Gestión (requiere sudo):

sudo systemctl status   twitch-stream-pipeline.service   # estado del pipeline
sudo systemctl restart  twitch-stream-pipeline.service   # reiniciar pipeline
sudo systemctl stop     twitch-stream-pipeline.service   # parar pipeline
sudo systemctl disable  twitch-stream-pipeline.service   # quitar auto-arranque

El bot API también tiene su propio servicio systemd:
sudo systemctl status   telegram-bot.service             # estado del bot
sudo systemctl restart  telegram-bot.service             # reiniciar bot
sudo systemctl stop     telegram-bot.service             # parar bot
sudo systemctl disable  telegram-bot.service             # quitar auto-arranque

Operación manual (alias de ~/.bashrc):
pipe_sys_start        # Arrancar el pipeline
pipe_sys_stop         # Parar todo
pipe_sys_status       # Ver estado
tg_bot_sys_start      # Arrancar el bot
tg_bot_sys_stop       # Parar el bot
tg_bot_sys_status     # Ver estado del bot

# Nota: tras pipe_recreate/pipe_up los contenedores ya están arriba; systemctl
# solo es una alternativa para gestionarlos. Detalle del servicio: ver README.md.

==============================================================================
  6. MONTAR EN OTRA MÁQUINA (Windows + WSL2)
 ==============================================================================

 Un SOLO script hace todo el montaje: clona el repo, ajusta las rutas a tu
 máquina, crea las carpetas de vídeo, revisa secretos, construye las imágenes,
 instala el servicio systemd (y lo habilita al boot) y añade los alias. Es
 IDEMPOTENTE: puedes lanzarlo las veces que quieras; solo hace lo que aún no
 esté hecho.

 --- Antes de nada en Windows (SOLO la primera vez) ---

   1. Instala WSL + Ubuntu. En PowerShell como ADMINISTRADOR:
        wsl --install -d Ubuntu
      (si ya tenías WSL:  wsl --update && wsl --set-default-version 2)
   2. Reinicia el PC si te lo pide. Al abrir Ubuntu crea tu usuario/contraseña.
   3. Instala Docker Desktop (Windows) y actívalo:
      Settings → Resources → WSL integration → activa tu distro (Ubuntu).
      Espera a que ponga "Engine running".
   NOTA: NO hace falta configurar systemd a mano. El script lo hace solo:
   en WSL escribe systemd=true en /etc/wsl.conf y te avisa si toca reiniciar.
   IMPORTANTE: el pipeline se arranca SOLO al encender el PC (systemd habilitado).
   Si lo prefieres a mano, usa `pipe_up` cuando quieras. El script instala el
   servicio systemd habilitado para el boot.

 --- Ejecutar el script (DENTRO de Ubuntu) ---

   Opción A — en una línea, sin descargar nada (RECOMENDADA):
       bash <(curl -fsSL https://raw.githubusercontent.com/jorbencas/devjobs/main/servicios/bootstrap_instalar.sh)

   Opción B — descargarlo y ejecutarlo como script:
       cd ~
       curl -fsSL -o bootstrap_instalar.sh https://raw.githubusercontent.com/jorbencas/devjobs/main/servicios/bootstrap_instalar.sh
       chmod +x bootstrap_instalar.sh      # <- DARLE PERMISO DE EJECUCIÓN
       ./bootstrap_instalar.sh

   Permisos que debes tener:
     - NO lo lances con sudo ni como root: usa tu usuario normal de Ubuntu.
     - El script usa sudo INTERNAMENTE (para instalar el servicio systemd en
       /etc/systemd/system y para escribir /etc/wsl.conf). Te pedirá tu
       contraseña cuando lo necesite → tu usuario debe poder usar sudo.
     - Opción A: NO necesita chmod (bash lee el contenido directamente).
     - Opción B: sí necesita chmod +x para poder lanzarlo como ./bootstrap...

   Qué hace el script, paso a paso (con confirmación en cada paso):
     1/8 Comprueba Docker y WSL2; si falta algo te dice qué instalar y se para.
     2/8 Clona el repo en ~/devjobs (o reutiliza el que ya exista; te pregunta).
     3/8 Sustituye la ruta fija /home/jorge/... por la de TU máquina.
     4/8 Crea las carpetas de vídeo (data/grabaciones/test y data/comprimidos).
     5/8 Revisa los secretos (config.bin/secret.key, uploader.session,
          grupos.json) y te dice cuáles faltan y cómo crearlos.
     6/8 Construye las imágenes Docker.
     7/8 Instala el servicio systemd (pero SIN habilitarlo al boot: lo
          arrancas a mano cuando quieras). En WSL sin systemd escribe
          [boot] systemd=true en /etc/wsl.conf y te pide hacer:
            wsl --shutdown        (desde PowerShell)
          Tras reiniciar, vuelve a lanzar el script UNA vez más y termina.
     8/8 Añade los alias del pipeline al ~/.bashrc.

 --- Después de terminar ---

   - Recarga los alias:                source ~/.bashrc
   - El pipeline se levanta SOLO al encender el PC (systemd habilitado).
   - Para arrancarlo tú a mano:         pipe_up
     (o con systemd:                    sudo systemctl start twitch-stream-pipeline.service)
   - Ver los logs de los 3 servicios:  plogs
   - Si no hay sesión de Telegram:     bash servicios/pipe_setup.sh
     (pide teléfono + código de verificación, SOLO la primera vez)
   - Arrancar el bot:                  tg_bot
     (o con systemd:                   sudo systemctl start telegram-bot.service)
   - Configurar el bot:                editar .env en downloader_telegram/ con BOT_TOKEN + GEMINI_API_KEY
   - Ver los vídeos generados en Windows:
     \\wsl$\<distro>\<tu_devjobs>\Videos\comprimidos
